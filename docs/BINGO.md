# 報到與賓果整合

目前一場活動可玩多局賓果；這些局次共用同一份名冊與報到狀態。多活動管理仍留待後續。

整合來源為使用者提供的 [fk8663212/bingobingo](https://github.com/fk8663212/bingobingo)，確認版本為 [`e86191a0656881fa52030fa3a7aca33ead64293f`](https://github.com/fk8663212/bingobingo/tree/e86191a0656881fa52030fa3a7aca33ead64293f)（新增開獎動畫）。沿用 5×5 卡片、中央免費格、1～49、不重複開獎、12 條連線判定、同回合超額抽選及動畫呈現；整合版將原本固定的 10 個名額改為每局可設定的獎品份數，介面改接本系統的票券、名冊與管理員登入。原專案程式與資料庫未修改。

## 網址與操作

| 畫面 | 路徑 | 權限 |
| --- | --- | --- |
| 個人電子票券 | `/ticket#個人憑證` | 持有本人有效票券 |
| 賓果卡／恢復入口 | `/bingo` | 領卡需有效票券及已報到 |
| 賓果主持台 | `/bingo/host` | 現有管理員帳號 |
| 投影 | `/bingo/display` | 公開唯讀 |

1. 管理員匯入活動名冊，發送原電子票券。工作人員依既有流程核對並確認報到。
2. 管理員登入後，從導覽列開啟「賓果主持台」，先設定「本局獎品份數」並按「儲存獎品份數」，再確認名單、按「開放領卡」。可選 1～200 份；第一局預設 10 份、關閉領卡。尚未儲存的修改會阻止本頁抽號。
3. 已報到的來賓開啟自己的電子票券；若頁面仍顯示待報到，按「更新報到狀態」。接著按「領取／開啟賓果卡」，無須另填姓名或取得另一組領卡碼。
4. 玩家可勾選卡片。重新整理保留卡片與已保存的記號，換裝置則再次開啟本人票券並按領卡按鈕。已領卡者在本局關閉領卡或開始開獎後仍可恢復原卡。
5. 主持人按「抽出下一個號碼」，待本次動畫完成再抽下一號。首次抽號自動關閉新領卡。投影與玩家頁依伺服器結果同步，背景頁返回時補查。
6. 系統判定得主後，由管理員核對本人、桌次與卡號，按「標記領獎」。公開投影只顯示卡號與領獎狀態，不顯示名冊姓名、單位或完整卡片。
7. 要再玩一局，按「開啟下一局」，選擇「下一局獎品份數」並完整輸入同名確認文字。份數預填上一局設定，建立前可改；取消不會建立新局。目前局次結束，歷史保留，保持已報到的既有玩家獲得新卡；新局預設關閉新領卡。可用「檢視局次」查看舊局並補登領獎。

同一瀏覽器已領另一位來賓的卡時，需先按「切換票券」，再使用本人的票券。這個操作不刪卡、不重設報到。票券仍屬持有即可使用的憑證，請勿轉傳；現場領獎應核對本人。

## 規則與異常

- 每局每位參加者一張卡。重複點擊、多分頁、換裝置及多人同時領同一張票，都恢復同一卡片。
- 手動勾選只供記號。連線依伺服器開獎號碼與首次達成的回合決定，沒有搶按中獎按鈕。
- 每局依設定的獎品份數決定得獎上限，每人最多得獎一次；同回合超額保存候選人、完整隨機順序及入選結果，重新整理不重抽。名額額滿或 49 個號碼全開出即結束。若獎品份數多於實際有效玩家，未用完的名額不會重複發給同一人。
- 第一個號碼開出前，只有管理員可調整本局份數；首次開獎後由伺服器鎖定，歷史局次也不能修改。份數調整與抽號共用 SQLite 寫入交易，多位主持人同時操作也不會在開獎後改動上限。
- 主持台、玩家規則及投影名額皆從伺服器讀取該局份數。份數保存在 SQLite，重新整理、重啟、備份／還原與完整紀錄匯出均保留；管理員設定及建立下一局會留下稽核。
- 報到撤回後，玩家現有登入也不能繼續操作，該卡不參與之後的新連線判定。原卡與所有已保存遊戲歷史保留，既有得獎不自動刪除；後續資格及已發獎項由管理員依現場情況處理。
- 票券補發後，舊連結及既有賓果登入失效。新票券仍連到同一位參加者，可以恢復同一張卡；不重設卡片或歷史。
- 未報到、無效票券或新領卡尚未開放時，顯示對應提示；不會自動完成報到。
- 領卡逾時時可安全重試。抽號帶有預期局次及回合，重送不會多抽一號；逾時後先等畫面恢復最新進度，再繼續主持。
- 勾選可在該裝置暫存，連線後再送出；新領卡、抽號及得獎判定需要連線。離線勾選不等於伺服器已保存，也不影響連線資格。

## 資料、部署與升級

使用原 Flask 服務及原 SQLite，新增 `bingo_games`、`bingo_cards`、`bingo_draws`、`bingo_winners`，稽核使用原 `audit_log`。原報到、名冊、帳號與票券資料不重建。既有 Dockerfile 會包含整個 `checkin/`；原持久化資料卷及兩個 Gunicorn worker 設定繼續使用，無須另外部署賓果伺服器。

升級前請先執行 README 的 SQLite 一致性備份，再停止所有本專案 worker，更新程式並重新啟動；啟動會新增資料表及一局尚未開放領卡的遊戲。兩份本機資料庫各自初始化，示範與正式名冊仍完全分開。原賓果專案的領卡碼、玩家及歷史未自動搬入整合版；舊資料留在原專案，整合版以目前報到名冊開始。

`backup-db` 現在同時涵蓋賓果，還原方式沿用 README。還原會撤銷工作人員登入及賓果登入，玩家需用還原後有效的票券恢復；卡片及遊戲回到備份時間。可接受整合前的完整報到備份並在下次啟動補齊新資料表；若備份只帶部分賓果資料表則拒絕還原。

主持台可用 POST「匯出完整紀錄」下載 JSON，包含各局、卡片、開獎及領獎；只有管理員可下載，不含票券 token、密碼或 session。含卡片內容與內部識別的匯出仍請私下保存。

獎品份數沿用既有 `bingo_games.max_winners`，不需要新增或清空資料表；既有局次保留原設定。更新後請重啟服務並重新整理主持台，讓新版表單與後端一併載入。

動畫來源為原專案的 `draw-animation.mjs`、`draw-animation.css`，狀態測試一併保留。整合後採每兩秒短輪詢，適用既有多 worker；架構決定見 [ADR-0002](adr/0002-integrated-bingo.md)。一般同步會有輪詢與網路延遲，動畫時間依伺服器已保存結果調整。

## 驗證

```sh
.venv/bin/python -m pytest -q
.venv/bin/python -m scripts.bingo_browser_smoke
.venv/bin/python -m scripts.bingo_server_smoke
node --test tests/bingo-animation.test.mjs
```

瀏覽器腳本需先依 README 安裝 Chromium／WebKit。全部使用隔離暫時資料，不操作現行活動。結果及限制見 [TEST_RESULTS.md](TEST_RESULTS.md)；實體手機、實際投影設備與 Oracle ARM VPS 仍需現場驗收。
