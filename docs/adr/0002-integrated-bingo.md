# 賓果沿用票券與報到資格，採同一資料庫及短輪詢

2026-10-20 決定：依使用者要求整合 `fk8663212/bingobingo`，資格為「完成報到後，使用原電子票券領卡」。此要求啟動原先延後的賓果工作，多活動管理仍維持延後。

整合版沿用原專案的連線規則、抽選方式、動畫與主要介面。將賓果資料放在報到 SQLite 的 `bingo_*` 資料表，以參加者的永久內部識別連結卡片；每局每人一張卡由唯一索引保證。名冊編號或票券補發不會產生另一位玩家。主持台使用現有管理員登入，工作人員不具主持權限。

另一個選擇是啟動原賓果伺服器，另發領卡碼並在兩份資料庫維護對應。採共用資料庫可在同一交易檢查票券及報到，也能讓既有一致性備份涵蓋完整活動；代價是部署升級需先備份，資料模型與既有報到版本一同演進。原專案及原資料庫保留，未自動合併其既有遊戲歷史。

原專案的 SSE 通知使用單程序記憶體狀態。報到系統既有兩個 Gunicorn worker、各四條執行緒，若保留長連線與程序內通知，會影響 200 人的同步及請求容量。整合版讓可見頁面每兩秒短輪詢，以資料庫已提交快照為準；背景頁暫停輪詢，返回時補查。代價是一般同步約有兩秒延遲，動畫仍依伺服器保存時間調整。

每次玩家存取都重新確認票券與報到。撤回報到停止後續遊玩與新連線判定，既有得獎、抽選及領獎紀錄保留。公開投影使用卡號呈現得主，管理員可查姓名及桌次。操作與驗收見 [賓果文件](../BINGO.md)。
